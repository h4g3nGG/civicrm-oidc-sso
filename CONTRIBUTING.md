# Contributing

Contributions should be provider-neutral and must not include deployment
identifiers, personal data, credentials or organization-specific mappings.

Changes to authentication, account linking, token validation or authorization
must include automated tests and a short threat analysis. Supported CiviCRM
APIs, documented hooks and extension mechanisms are preferred. Calls to
undocumented CiviCRM internals require prior discussion and must not be merged
into a stable release without a documented compatibility strategy.

All contributions are licensed under `AGPL-3.0-or-later`.

By participating, contributors agree to follow the
[Code of conduct](CODE_OF_CONDUCT.md). Suspected vulnerabilities must be sent
privately as described in [SECURITY.md](SECURITY.md), not submitted as public
issues or pull requests.
